# バージョニングおよび変更管理ルール (Versioning & Change Management Rules)

Antigravity で作成・保守するスクリプト、プロンプト、exe ファイル、および成果物には、以下の規則に従ってバージョン番号を付与・更新します。

---

## 1. バージョン採番形式
セマンティックバージョニング形式（`v○.○.○`）を使用します。

- **初期値**: `v1.0.0`（※ 既存プロジェクトで既に進行している場合は現在のバージョンを基準とする）
- **バグフィックス・軽微な修正 (Patch)**: `0.0.1` の位をインクリメント（例: `v1.0.0` → `v1.0.1` / `v1.6.0` → `v1.6.1`）
  - バグ修正、軽微なリファクタリング、タイポ修正、動作を変えない調整など
- **機能追加・拡張 (Minor)**: `0.1` の位をインクリメントし、パッチを 0 にリセット（例: `v1.0.1` → `v1.1.0` / `v1.6.1` → `v1.7.0`）
  - 新機能の追加、既存機能の拡張、オプションや引数の追加など
- **メインバージョンアップ (Major)**: **ユーザーの指示に従って** メジャー番号をインクリメントし、マイナー・パッチを 0 にリセット（例: `v1.2.3` → `v2.0.0`）
  - 破壊的変更、アーキテクチャの全面刷新、大規模リニューアルなど

---

## 2. 各成果物へのバージョン記載ルール

### (1) スクリプトファイル (`.py`, `.sh`, `.bat`, `.ps1` 等)
- ファイルヘッダー（docstring または冒頭のコメント）にバージョンと更新履歴（更新日・概要）を明記する。
- 内部変数（例: `__version__ = "v1.6.0"`）を定義する。

### (2) プロンプト (`.txt`, `.md`, `.json` 等)
- ファイル冒頭またはメタデータ部にバージョン情報（`Version: v1.0.0`）を明記する。

### (3) exe ファイル (実行可能バイナリ) / 配布物
- ビルド時にバージョン情報リソース（ファイルバージョン / 製品バージョン）を埋め込む。
- 出力ファイル名や配布ZIPにバージョンを付与する（例: `シフト自動生成_v1.6.0.zip`）。

---

## 3. GitHub / Git バージョン管理ルール

1. **コミットメッセージ**:
   - バージョンアップを伴う変更時は、コミットメッセージにバージョン番号と変更種別（Fix, Add, Feat, Major など）を明記する。
   - 例: `feat: シフト制約レベルの拡張 (v1.7.0)` / `fix: 祝日判定ロジックの修正 (v1.6.1)`
2. **Git タグ (Git Tag)**:
   - バージョンが確定・リリースされるタイミングで、対応する Git タグ（`git tag -a v○.○.○ -m "Release v○.○.○"`）を付与する。
3. **リモートへのプッシュ**:
   - 変更内容をコミット後、タグとともにリモートリポジトリ（GitHub）へプッシュする。
